# Hephaestus + driving-force dropdown (2026-07-30)

Two additions shipped together (build clean, service restarted, plumbing verified end-to-end up to the model call).

## Hephaestus — the coding specialist
Cloned from Atlas in `container/agent-runner/src/index.ts` (`SUBAGENTS` entry, `hephaestus-core` toolset in `toolsets.ts`). Async background agent like Atlas; both share one `backgroundJobs` map + `spawnBackgroundJob(delegate, …)` (renamed from the atlas-only `spawnAtlasBackgroundJob`). Atlas keeps Bash + desktop/app control; Hephaestus owns code-editing (`file` toolset = Read/Write/Edit/Glob/Grep, which atlas-core lacks) + builds/tests + heavy scripting. Both inherit the `data/skills/` library via the same skill-merge. Hephaestus has its **own model dropdown** (`hephaestus:model` router_state → `HEPHAESTUS_MODEL`, falls back to orchestrator) — intended for a frontier cloud model, NOT the shared Chat Model. Orchestrator routing: roster bullet, "when in doubt → atlas except coding → hephaestus", a coding cue word, and the PII-local line now covers both cloud agents.

## Driving force — orchestrator preamble dropdown
`data/driving-forces/*.md` presets replace the orchestrator's `# ROLE` preamble; the roster + routing core stays fixed (swap HOW it thinks, not WHO it delegates to). Empty id = "Warden (default)" = the in-code `DEFAULT_PREAMBLE` (preserves the dynamic `assistantName`). Settings GET returns `drivingForce` + `drivingForces` (read from the dir, label = first H1); no separate list endpoint. Switching the driving force clears context: `status-server` sets `orchestrator:context_clear_at` + advances `last_agent_timestamp`; the host's `buildPrompt` gates `<chat_history>` on that marker; the agent-runner's `buildSystemPrompt()` reads the preset file and the `_clearContextRequested` flag (set on a changed `contextClearAt` via `applySettingsSync`) resets the in-memory `messages` to a fresh system prompt at the top of the orchestrator loop — which also finally wires up the previously-dead `clear_context` tool. Note: a router-state save respawns the agent-runner child (`restart:true`), so the driving-force change is usually picked up by a fresh child; the in-loop clear is the belt-and-suspenders for non-restart cases.

Presets: staff-engineer, first-principles, paranoid-reviewer, ship-it, architect, debugger, socratic, mentor.
